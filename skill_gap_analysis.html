Skill Gap Analysis

Skill Gap Analysis

This analysis evaluates how well the team’s current skills align with the skills most frequently requested for Data Engineer-related roles in the Insurance industry.

The analysis began with 1,908 Insurance industry job postings. To focus on our target career, the dataset was filtered to Data Engineer and closely related positions, including Data Engineering, Analytics Engineer, Data Platform Engineer, ETL Engineer, and Data Warehouse Engineer roles. This resulted in 29 Data Engineer-related job postings used for the market skill analysis.

The analysis focused on the following Data Engineering skills:

Python, SQL, ETL/Pipelines, Cloud Computing, Spark/PySpark, Databricks, Data Modeling, Databases/Snowflake, Git/CI-CD, and Data Quality/Governance.

Scoring Method

Each team member rated their current proficiency using a 1–5 scale:

  • 1 = Beginner
  • 2 = Basic Knowledge
  • 3 = Intermediate
  • 4 = Advanced
  • 5 = Expert

The individual ratings were averaged to calculate the Team Average for each skill.

Market demand was calculated by measuring the percentage of the 29 relevant job postings that mentioned each skill. The percentages were then converted to a 1–5 market-demand scale:

  • 1 = Less than 20% of postings
  • 2 = 20%–39.9%
  • 3 = 40%–59.9%
  • 4 = 60%–79.9%
  • 5 = 80%–100%

The Market Score measures how frequently employers request a skill; it does not represent the proficiency level employers expect.

The skill gap was calculated as:

Skill Gap = Market Score − Team Average

If the Team Average was greater than the Market Score, the gap was recorded as zero.

Development priority was classified as:

  • High Priority: Skill Gap ≥ 2
  • Moderate Priority: Skill Gap ≥ 1 and < 2
  • Low Priority: Skill Gap < 1

A larger gap therefore represents a skill that appears frequently in the analyzed job postings but where the team’s current proficiency is comparatively lower.

# Calculate market demand for each skill
market_results = []

total_postings = len(data_engineer_jobs)

for skill, pattern in skill_patterns.items():

    count = (
        data_engineer_jobs["ALL_SKILLS"]
        .str.contains(pattern, regex=True, na=False)
        .sum()
    )

    percentage = (
        count / total_postings * 100
        if total_postings > 0
        else 0
    )

    market_results.append({
        "Skill": skill,
        "Postings": count,
        "Market Demand %": round(percentage, 2)
    })

market_df = pd.DataFrame(market_results)


# Convert market-demand percentage to 1–5 score
def market_score(percentage):

    if percentage >= 80:
        return 5
    elif percentage >= 60:
        return 4
    elif percentage >= 40:
        return 3
    elif percentage >= 20:
        return 2
    else:
        return 1


market_df["Market Score"] = (
    market_df["Market Demand %"]
    .apply(market_score)
)

# Calculate team average for comparable skills
comparison_skills = list(skill_patterns.keys())

team_average = (
    df_skills[comparison_skills]
    .mean()
    .round(2)
)

team_average_df = team_average.reset_index()

team_average_df.columns = [
    "Skill",
    "Team Average"
]

# Combine team and market results
skill_gap_df = pd.merge(
    team_average_df,
    market_df,
    on="Skill",
    how="inner"
)

# Calculate skill gap
skill_gap_df["Skill Gap"] = (
    skill_gap_df["Market Score"]
    - skill_gap_df["Team Average"]
).clip(lower=0).round(2)


# Assign development priority
def gap_priority(gap):

    if gap >= 2:
        return "High"
    elif gap >= 1:
        return "Moderate"
    else:
        return "Low"


skill_gap_df["Priority"] = (
    skill_gap_df["Skill Gap"]
    .apply(gap_priority)
)

Key Findings

The largest measured skill gaps are in Cloud Computing, Python, Git/CI-CD, and Spark/PySpark. These skills combine strong market demand with relatively low current team proficiency and therefore represent the highest development priorities.

ETL/Pipelines shows a moderate gap. Although it appears frequently in the analyzed job postings, the team’s current proficiency is stronger than in the highest-priority areas.

The team’s SQL proficiency is relatively close to its market-demand score, resulting in only a small measured gap.

Data Quality, Data Modeling, DB/Snowflake, and Databricks show little or no measured team-level gap under this scoring method.

Insurance Knowledge was included in the team’s self-assessment but excluded from the quantitative market comparison because the structured job-posting skill fields do not provide a directly comparable measure of Insurance domain knowledge.

Because the market comparison is based on 29 Data Engineer-related postings, the results describe the skills observed in this analyzed sample rather than every Data Engineer position in the broader Insurance job market.
